## notarize_binary.sh

Script to automate Apple Notarization process.

You can store your password in the keychain for easier process.
You will first have to generate an app-specific password:
- Sign in to your [Apple ID account page](https://appleid.apple.com/account/home).
- In the Security section, click Generate Password below App-Specific Passwords.
- Follow the steps on your screen.
- Store the generate app-specific password in the keychain using this command
  - xcrun altool --store-password-in-keychain-item "AC_PASSWORD" -u _"YourAppleID"_ -p _"GeneratedPassword"_

`Usage: notarize_binary.sh <Binary Path> <User Name> <Password> <Notarization Bundle Identifier>`
- `<Binary Path>` is the path to the binary you want to notarize. It should either be a zip, an application bundle, or a dmg
- `<User Name>` is _YourAppleID_
- `<Password>` is "@keychain:AC_PASSWORD"
- `<Notarization Bundle Identifier>` is any bundle identifier you want (might be different than the actual application)

## publish_nuget.sh

Script to build and publish the NuGet package of a CMake target (`<name>[-debug]-<RID>`), using the `<target>-nuget-push` target generated by `cu_generate_csharp_nuget_target`, `cu_generate_native_nuget_target` or `cu_generate_plugin_nuget_target` (cmakeUtils).
The package is selected with `-l <libName>` (C# bindings of the library, `<libName>-csharp` target) or `-t <target>`.
A calling script publishing several packages declares their names in the `nugetPackages` array and configures the one selected with the mandatory `-package <name>` option in the `extend_pn_fnc_select_package` function (see the script header for the details):
```bash
nugetPackages=("csharp" "plugin")
function extend_pn_fnc_select_package()
{
	case "$1" in
		csharp)
			libName="la_myLib"
			add_cmake_opt+=("-DBUILD_LAMYLIB_SWIG=TRUE" "-DLAMYLIB_SWIG_LANGUAGES=csharp")
			;;
		plugin)
			targetName="myLibServicePlugin"
			add_cmake_opt+=("-DBUILD_LAMYLIB_SERVICE_PLUGIN=TRUE")
			;;
	esac
}
```
The `-meta` option generates and publishes the meta-package of the selected package instead (see `publish_nuget_meta.sh`).

`Usage: publish_nuget.sh -s <source> [-l <libName>|-t <target>|-package <name>] [options] -- [cmake options]`

## publish_nuget_meta.sh

Script to generate and publish a NuGet meta-package (`<name>[-debug]`) referencing all the RID specific packages (`<name>[-debug]-<RID>`) already published on a NuGet source, so consumers don't need any RID logic.
For each OS, the universal package (for example `osx`) is selected when published with the meta-package version, otherwise all the architecture specific ones (for example `osx-arm64` and `osx-x64`).
The meta-package also copies the native assets of the package best matching the consumer `RuntimeIdentifier` (or the machine running the build when none is set) to its output folder root, keeping their layout (subfolders of `runtimes/<RID>/native/`).
The selected package is the one of the exact RID, else the universal one of the operating system, else the x64 one on Windows and macOS arm64 (which run x64 binaries through emulation).
Run it from a folder whose `NuGet.config` files give access to the source, after all the RID specific packages of the version have been published (also available through `publish_nuget.sh -meta`).

`Usage: publish_nuget_meta.sh -n <name> -s <source> [-k <apiKey>] [-c Debug|Release] [-v <version>] [-o <workFolder>] [-no-push] [-no-clean]`
